# 面试问答要点

> 用途：面试前的讲述提纲 + 预设追问的标准答案。
> 注意：文中"实测数字"（50%→85%、5s→12s、0.08元/次）是**目标口径，以 M6 产出的《评估报告》实测数据为准**，评估做完后必须替换成真实数字，面试前核对一遍。

## 1. 一分钟版本（电梯陈述）

"我做了一个多 Agent 旅行规划助手：用户输入一句话，比如'国庆去成都玩3天预算3000'，三个 Agent 顺序协作——Planner 负责理解需求和编排行程，Info 负责拿结构化的景点/美食/酒店数据，Budget 负责费用估算，超预算就回环让 Planner 调整。Agent 间全用 JSON 通信，任何一个工具挂了都有兜底数据，流程不会断。对比单 LLM 直出，行程合理率从大约 50% 提到 85%，代价是耗时从 5 秒变 12 秒左右。"

## 2. STAR 展开

- **任务（痛点）**：做旅行攻略要在多个 App 间横跳，信息分散、预算容易超。目标：一句话进、完整行程单出、预算可控。
- **基线**：同一个 LLM 单次直出行程，50 条测试用例上合理率约 50%——常见问题是编造景点、预算严重失真、一天塞 6 个景点。
- **方案**：3 个 Agent 顺序协作（不做复杂动态编排）+ JSON 通信 + 预算兜底回环。关键取舍：**只有两处用 LLM**（参数抽取、行程编排），子任务拆解、费用估算、预算调整全是确定性代码。
- **个人贡献**：独立完成全部设计开发；其中最有含金量的是 Planner 的任务拆解逻辑（哪步用 LLM、哪步用代码的成本划分）和 Budget 的费用估算规则（分项公式 + 4 级调整优先级 + 2 轮回环上限）。
- **结果**：50 条用例，任务合理率 50%→85%；平均耗时 5s→12s；单任务成本约 0.08 元（LLM 调用收敛在 2~3 次）。
- **反思**：1~2 天的简单请求走多 Agent 又慢又贵，v1.1 加了路由：≤2 天直接单 LLM 生成。教训是"多 Agent 是手段不是目的"。

## 3. 预设追问 Q&A

**Q1：为什么不用 LangChain / AutoGen 这类框架？**
项目规模小，框架带来的抽象层比业务逻辑本身还复杂。手写编排器只有约 40 行，每一行都能讲清楚；不依赖框架反而逼我把 Agent 边界、通信协议、失败处理想明白。这本身就是这个项目的学习目的。

**Q2：为什么是 3 个 Agent，不是 1 个或 5 个？**
按职责单一原则切：规划（理解+编排）、信息（取数+兜底）、预算（算钱+校验）是三种性质不同的工作——前两种要 LLM/外部数据，第三种是纯规则。1 个 Agent 职责混杂、prompt 臃肿；再加 Agent（比如单独的"天气 Agent"）没有独立决策点，只会增加通信开销。

**Q3：Agent 间为什么用 JSON 通信而不是自然语言？**
自然语言传递会有信息损耗和解析不确定性。JSON + pydantic 强校验，下游拿到的数据要么合法要么触发重试，失败路径清晰。统一的消息信封（msg_type/sender/receiver/payload）也方便打日志排查。

**Q4：数据源是模拟的，怎么证明架构有效？**
两点。第一，工具接口按真实 API 的形状设计（异步、超时、重试、兜底），有故障注入开关可以现场演示降级；接真实数据源只改 tools/ 层，Agent 层零改动。第二，评估对比的是"有没有结构化候选数据 + 预算校验闭环"带来的合理率差异，这个结论对数据源是否真实不敏感。

**Q5：LLM 输出不稳定怎么办？**
三层：pydantic 校验 → 把校验错误拼回 Prompt 定向重试 1 次 → 降级到代码模板（行程编排）或追问用户（参数抽取）。降级生成的行程会在输出里明确标注。实测绝大部分失败在第一层重试就解决。

**Q6：多 Agent 比单 LLM 慢（5s→12s），为什么还要用？**
慢换来的是合理率和可控性：候选数据约束住了幻觉，预算回环约束住了开销。而且 12 秒里大头是两次 LLM 调用的固有延迟，不是架构开销——回环调整是纯代码，几乎零耗时。对 3 天以上的复杂行程，用户对 12 秒不敏感。

**Q7：预算回环为什么上限 2 轮？**
实测超标场景一轮降档/换免费景点就能解决；两轮还超说明预算本身不现实，继续循环只会浪费时间。此时输出"预算过紧，最低可行预算约 X 元"，把决策交还用户，这比硬凑一份行程诚实。

**Q8：如果要支持 100 并发，架构要改什么？**
编排器从同步改异步是第一步（接口已经按 async 设计）；三个子任务可以并发取数；再加结果缓存（同城市候选数据可缓存）；LLM 调用做限流和降级排队。架构分层的好处是这些都只动编排层和工具层。

**Q9：这个项目最大的不足是什么？**
数据是离线的，价格和评分是静态估价；评估用例只有 50 条、合理性标准是自定 checklist，主观成分仍在。改进方向是接真实数据源、扩大用例集、引入人工评分交叉验证。
